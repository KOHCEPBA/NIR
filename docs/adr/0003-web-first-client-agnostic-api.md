# ADR-0003: Web-first и независимый от клиента API

**Date**: 2026-04-25
**Status**: accepted
**Deciders**: автор проекта, проектная команда

## Context

В MVP требуется только web-клиент, но позднее может появиться мобильное приложение. Контракты не должны зависеть от внутреннего устройства web-интерфейса.

## Decision

Разрабатывать web-клиент первым, а внешний REST API версионировать и проектировать независимо от типа клиента. Клиенты используют одинаковые доменные ресурсы и токены доступа через Backend API.

## Alternatives Considered

### API только под web-клиент

- **Pros**: быстрее адаптировать ответы под конкретные экраны.
- **Cons**: мобильный клиент потребует переработки контрактов.
- **Why not**: ограничивает заявленное развитие системы.

### Отдельный backend для каждого клиента

- **Pros**: оптимальные контракты для каждой платформы.
- **Cons**: дублирование логики на этапе MVP.
- **Why not**: преждевременно; BFF можно добавить при подтвержденной необходимости.

## Consequences

### Positive

- Мобильный клиент можно подключить без изменения доменного API.
- Контракты документируются OpenAPI и тестируются независимо.

### Negative

- API не всегда повторяет структуру конкретного экрана.
- Требуется дисциплина совместимости версий.

### Risks

- Слишком общий API; снижается проектированием по пользовательским сценариям и измерением числа запросов клиента.
