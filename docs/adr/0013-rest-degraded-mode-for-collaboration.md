# ADR-0013: REST degraded mode при сбое real-time доставки

**Date**: 2026-06-18
**Status**: proposed
**Deciders**: автор проекта, проектная команда

## Context

В модульном монолите REST и STOMP обслуживаются одним backend-процессом, поэтому отдельный отказ Collaboration не является самостоятельным runtime-сценарием. При обычном сетевом разрыве клиент переподключается и выполняет REST resync. Полноценный degraded mode становится полезен, если Collaboration будет выделен в отдельный сервис и сможет отказать независимо от Curriculum API.

## Decision

Рассматривать degraded mode как вариант для будущего выделенного Collaboration Service: при его недоступности отключать presence, продолжать REST-команды с `If-Match` и периодически выполнять conditional GET с `If-None-Match`. До выделения сервиса web-клиент не включает polling: он пытается восстановить STOMP-соединение и после reconnect выполняет REST resync перед применением новых событий.

## Alternatives Considered

### Блокировать редактор без WebSocket

- **Pros**: клиент не работает с потенциально устаревшим live-состоянием.
- **Cons**: вспомогательный канал становится критической зависимостью всех изменений.
- **Why not**: REST и PostgreSQL остаются источником истины и способны безопасно разрешать конфликты через ETag.

### Постоянный частый polling

- **Pros**: единый механизм обновления независимо от WebSocket.
- **Cons**: лишняя нагрузка и задержка обновлений при нормальной работе.
- **Why not**: polling нужен как резервный, а не основной канал.

### Локальная очередь offline-изменений

- **Pros**: пользователь может редактировать при полной недоступности backend.
- **Cons**: требуется сложное слияние операций, разрешение конфликтов и надежное локальное хранение.
- **Why not**: offline-first редактирование не входит в MVP.

## Consequences

### Positive

- При выделении Collaboration его сбой ухудшает UX, но не блокирует редактор.
- `If-Match` предотвращает незаметную перезапись чужих изменений.
- Conditional GET ограничивает трафик ответами `304 Not Modified`.

### Negative

- Решение не реализуется, пока Collaboration остается модулем монолита.
- При будущем degraded mode обновления других пользователей будут видны с задержкой.
- Web-клиент содержит state machine подключения, polling с jitter и логику resync.
- Presence временно недоступен.

### Risks

- События после reconnect могут примениться к устаревшей ревизии; клиент сначала получает актуальное состояние через REST и игнорирует дубликаты/старые revision.
- Множество отключенных клиентов может синхронно начать polling; используются интервалы 5, 15 и 30 секунд с jitter.
