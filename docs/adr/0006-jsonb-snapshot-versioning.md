# ADR-0006: JSONB snapshot-версионирование

**Date**: 2026-05-13
**Status**: accepted
**Deciders**: автор проекта, проектная команда

## Context

Версия создается пользователем по кнопке и должна фиксировать весь план вместе с результатами проверки. Согласование относится к сохраненной версии, пока рабочий план может изменяться дальше.

## Decision

Хранить каждую версию как неизменяемый полный JSONB-снимок с номером схемы, исходной ревизией, автором, комментарием, результатами проверки и хешем содержимого.

## Alternatives Considered

### Копии всех нормализованных строк

- **Pros**: обычные SQL-запросы к историческим данным.
- **Cons**: сложная схема, много таблиц и дорогая эволюция модели.
- **Why not**: избыточно для редких ручных snapshot в MVP.

### Журнал всех операций

- **Pros**: полная история и возможность воспроизведения состояния.
- **Cons**: сложность event sourcing, миграции событий и восстановления.
- **Why not**: не требуется для упрощенной модели совместного редактирования.

## Consequences

### Positive

- Простое атомарное создание и чтение версии.
- Согласуемая версия не зависит от дальнейших правок черновика.

### Negative

- Дублирование данных между версиями.
- Аналитические запросы по содержимому истории сложнее.

### Risks

- Изменение структуры snapshot; управляется обязательным `schema_version` и преобразователями при чтении или восстановлении.
