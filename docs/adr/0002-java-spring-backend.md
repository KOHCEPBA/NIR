# ADR-0002: Java и Spring для backend

**Date**: 2026-04-24
**Status**: accepted
**Deciders**: автор проекта, проектная команда

## Context

Backend должен поддерживать REST, WebSocket, безопасность, реляционные данные и последующее промышленное развитие. Для проекта выбран единый технологический стек модульного приложения и возможных выделенных сервисов; интеграция с Kafka остается необязательной.

## Decision

Использовать Java 21 и Spring Boot как основной backend-стек, включая Spring Web, WebSocket, Security и Data JPA. Реализовать package-based Spring Modulith modules в одном backend build; границы контролировать Spring Modulith и ArchUnit, миграции модульных схем выполнять Flyway.

## Alternatives Considered

### Kotlin и Spring

- **Pros**: компактный синтаксис и совместимость с JVM.
- **Cons**: дополнительный язык и более высокий порог входа для команды.
- **Why not**: Java лучше соответствует заявленному учебному стеку.

### C# и ASP.NET Core

- **Pros**: зрелая web-платформа и хорошая производительность.
- **Cons**: другой стек и экосистема.
- **Why not**: не соответствует выбранной специализации проекта.

## Consequences

### Positive

- Единая зрелая экосистема для всех backend-задач.
- Хорошая поддержка PostgreSQL, Kafka и observability.
- Автоматическая проверка допустимых зависимостей между модулями.

### Negative

- JVM-приложения требуют больше памяти, чем некоторые альтернативы.
- Необходимо управлять совместимостью версий Spring-зависимостей.

### Risks

- Разрастание шаблонного кода; снижается едиными стартерами, соглашениями и общими библиотеками только для технических аспектов.
