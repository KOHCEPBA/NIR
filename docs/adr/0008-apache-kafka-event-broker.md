# ADR-0008: Apache Kafka как брокер событий

**Date**: 2026-05-22
**Status**: proposed
**Deciders**: автор проекта, проектная команда

## Context

Текущая архитектура является модульным монолитом и не требует внешнего брокера для взаимодействия модулей. Kafka может понадобиться позднее для подтвержденных межпроцессных интеграций, нескольких независимых consumers или долговечного журнала с replay, но таких требований пока нет.

## Decision

Рассматривать Apache Kafka как кандидатный брокер для будущих интеграционных и межпроцессных событий. Решение принимается после появления конкретного сценария и сравнения с DB-backed job queue, RabbitMQ и возможностями инфраструктуры ВУЗа. До принятия решения модули используют публичные application API и внутрипроцессные события, а Kafka не входит в обязательную инфраструктуру ни одного релиза.

## Alternatives Considered

### RabbitMQ

- **Pros**: простая маршрутизация команд и очередей, ниже порог эксплуатации.
- **Cons**: модель меньше ориентирована на долговечный журнал и повторное чтение.
- **Why not**: окончательный выбор откладывается до появления требований к маршрутизации, replay и профилю нагрузки.

### Redis Streams

- **Pros**: можно переиспользовать Redis, простая инфраструктура MVP.
- **Cons**: слабее экосистема и эксплуатационные возможности для основного event backbone.
- **Why not**: окончательный выбор откладывается; Redis Streams не рассматривается как основной вариант без подтвержденного сценария.

## Consequences

### Positive

- При принятии решения будут доступны долговечные события, replay и независимые consumer groups.
- Контракт событий можно подготовить без преждевременного развертывания брокера.

### Negative

- До принятия ADR нельзя проектировать функцию так, будто Kafka гарантированно доступна.
- Нужно проектировать ключи партиционирования и совместимость схем событий.

### Risks

- Kafka может быть выбрана без достаточного основания; перед переводом ADR в `accepted` фиксируются consumers, объемы, требования replay и эксплуатационная ответственность.
