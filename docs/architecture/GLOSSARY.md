# Глоссарий

| Термин | Значение |
|---|---|
| Учебный план | редактируемый набор блоков, дисциплин, периодов, нагрузки, форм контроля и пререквизитов для программы, направления и года набора |
| Рабочая ревизия | текущее изменяемое состояние учебного плана с монотонно растущим номером `revision` |
| Row version | версия отдельной изменяемой сущности для optimistic locking; не меняется при обновлении других сущностей плана |
| Snapshot-версия | неизменяемая JSONB-копия учебного плана, созданная пользователем из конкретной рабочей ревизии |
| Content hash | SHA-256 канонического snapshot для проверки целостности и равенства содержимого; не является электронной подписью |
| Учебный модуль | период учебного года; в текущей модели используется четыре модуля на год |
| Промежуточная валидация | синхронная проверка текущей рабочей ревизии без создания версии |
| Outcome | агрегированный результат проверки: `ACCEPT`, `WARNING` или `ERROR` |
| Staging | изолированное нормализованное представление импорта до явного атомарного применения |
| Presence | список пользователей, у которых открыт редактор конкретного плана |
| ETag | HTTP-представление версии изменяемого ресурса для optimistic locking |
| Authorization context | набор `user_id`, roles и scopes, сформированный Identity и доступный прикладным модулям в доверенном backend-контексте |
| Модульный монолит | одно развертываемое приложение с технически контролируемыми границами бизнес-модулей |
| Извлекаемый модуль | модуль, чьи API и данные изолированы достаточно для последующего выделения в отдельный сервис при наличии причины |
| DB-backed job queue | долговечная очередь фоновых заданий в PostgreSQL с атомарным созданием job, lease, retry и восстановлением после сбоя |
| Degraded mode | proposed-режим для выделенного Collaboration Service: REST остается доступным, а клиент временно использует polling без live-доставки |
| Outbox/inbox | шаблон надежной публикации и идемпотентной обработки событий относительно локальных транзакций БД |
| DLT | Kafka topic для сообщений, которые consumer не смог обработать после retry либо признал non-retryable |
| C4 container | независимо исполняемое приложение или хранилище на логической диаграмме C4; не обязательно Docker-контейнер |
| MVP | минимальный релиз редактора, проверки, snapshot-версий, тепловой карты и одного экспорта |
| Post-MVP 1 | релиз совместной работы, импорта и расширенного версионирования |
| Post-MVP 2 | релиз согласования, администрирования правил и дополнительных интеграций |
